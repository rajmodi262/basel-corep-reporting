# Functional Specification — COREP own funds and leverage reporting

## 1. Purpose

Produce Demo Bank AG's quarterly COREP submission for **own funds** (C 01.00, C 02.00, C 03.00)
and the **leverage ratio** (C 47.00) under the EBA reporting framework 4.0. Produce it from the
bank's general ledger and risk sub-ledger, prove that it ties back to them, pass the EBA's own
validation rules, and deliver it in the EBA's xBRL-CSV format.

## 2. Regulatory basis

| Topic | Regulation |
|---|---|
| Own funds, deductions, tiers | CRR Part Two, Art 25-91 |
| Credit risk, Standardised Approach | CRR Part Three, Title II, Chapter 2, Art 111-134 |
| Operational risk, Business Indicator | CRR Part Three, Title III, Art 312-316 (CRR3) |
| Capital ratios | CRR Art 92 |
| Pillar 2 and buffers | CRD Art 104, 104a, 128-141 |
| Leverage ratio | CRR Part Seven, Art 429-429g |
| Templates, datapoints, validation rules | EBA reporting framework 4.0, taxonomy errata 5 |

## 3. Scope

| In scope | Out of scope (the bank has no such business) |
|---|---|
| C 00.01, C 01.00, C 02.00, C 03.00, C 22.00, C 25.01, C 34.01, C 34.03, C 47.00 | Trading book (other than FX), securitisation, IRB, IMM |
| Standardised Approach credit risk incl. off-balance items | Large exposures, liquidity (LCR/NSFR), FINREP |
| Counterparty credit risk (SA-CCR), CVA (simplified), FX risk (CR-002) | Consolidation (individual-level report) |
| BIC operational risk | Margined netting sets, collateral |

## 4. Functional requirements

| ID | Requirement | Verified by |
|---|---|---|
| FR-01 | Extract the reported templates' datapoints and validation rules from the official EBA taxonomy into versioned files | `scripts/extract_taxonomy.py`, `taxonomy/` |
| FR-02 | Run data-quality rules first; BLOCK rules stop the run, WARN rules apply a documented conservative fallback | DQ-01..10, `docs/DATA_GAPS.md` |
| FR-03 | Classify every exposure with a decision table held as data; first matching rule wins | UT-05, UT-06, `config/dt_exposure_class.csv` |
| FR-04 | Assign risk weights per CRR Art 114-134, including Art 114(4), Art 125 loan-splitting and the Art 127 cover test | UT-01..UT-09 |
| FR-05 | Compute operational risk with the BIC from three years of P&L | UT-11 |
| FR-06 | Build own funds from the GL via a mapping table with one sign convention; apply Art 26(2), 36, 48 and 64 | UT-10, UT-12, UT-13 |
| FR-07 | Compute capital ratios and the requirement stack (Pillar 1, P2R, CBR, P2G) | UT-14 |
| FR-08 | Compute the leverage exposure measure and ratio | UT-15 |
| FR-09 | Reconcile the report to the books: sub-ledger to GL by account, balance sheet to leverage exposure, equity to own funds, P&L to the business indicator, loan-level RWEA to the template | REC-01..08, UT-21 |
| FR-10 | Evaluate every EBA validation rule on the reported templates with interval arithmetic; no FAIL allowed | UT-16..UT-20 |
| FR-11 | Write xBRL-CSV report packages (one per module) in the EBA layout; byte-reproducible | UT-23, UT-24 |
| FR-12 | Keep a trace of how each derived number was calculated | `out/calculation_trace.json` |
| FR-13 | Change control: every regulatory or data change carries an impact list agreed in advance; the change is accepted only if exactly those cells move | `scripts/impact_analysis.py`, UT-25..UT-29, `docs/changes/` |
| FR-14 | Use a property valuation only if it is no older than 3 years at the reference date | DQ-09, UT-29 |
| FR-15 | Compute counterparty credit risk with SA-CCR per netting set and report it in C 02.00 and C 34.03 | UT-30, UT-31 |
| FR-16 | Include derivatives in the leverage exposure with the PFE multiplier set to 1; exclude derivative assets from r0190 | UT-32, REC-04 |
| FR-17 | Compute CVA risk with the simplified approach, excluding exempt non-financial counterparties; justify eligibility with the monthly size test (C 34.01) | UT-33, UT-36 |
| FR-18 | Compute FX risk on the whole balance sheet, applying the 2% de minimis | UT-34, UT-35 |

## 5. Outputs (`out/`)

| File | Content |
|---|---|
| `*_COREPOF_*.zip`, `*_COREPLR_*.zip` | The submission: xBRL-CSV report packages |
| `corep_templates.csv` | Every reported cell with its label and datapoint, readable |
| `eba_validation_results.csv` | Each EBA rule: pass / FAIL / not applicable, with the values used |
| `reconciliation.csv` | REC-01..08 |
| `data_quality.csv` | DQ-01..10 with example exposure ids |
| `credit_risk_by_exposure.csv` | Exposure class, risk weight and RWEA per exposure (and per mortgage part) |
| `calculation_trace.json` | How derived figures were computed |
| `summary.json` | Headline figures |

## 6. Assumptions (stated, not hidden)

- The bank is fictional; its books are generated by `scripts/generate_bank.py` (fixed seed).
- External ratings are already mapped to credit quality steps.
- Specific provisions are the IFRS 9 stage 3 allowances; there are no general credit risk adjustments.
- Supervisory parameters (P2R 2%, CCyB 1.00% after CR-001, P2G 1%) are illustrative, not any real bank's SREP decision.
- The software prudent-amortisation treatment is not claimed: software is deducted in full (conservative).
